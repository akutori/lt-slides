# FAXとは?

- 文書・画像を**電話回線**で送受信する技術
- 発明は **1843年** — 電話（1876年）より **33年** も前！
- 発明者：イギリスの時計技師 **アレクサンダー・ベイン**
- 現代の G3 FAX 規格は **1980年** に標準化
- 日本では **1985年** の規制緩和で一気に普及

# FAXの仕組み

## 「画像を音に変換して電話線で送る」

1. 原稿をスキャンして **白黒の2値データ** に変換
2. **モデム** でアナログ音声信号に変換（変調）
3. **電話回線** で音として送信
4. 受信側の **モデム** がデジタルデータに復元（復調）
5. データを受信して **プリントアウト**

<!-- つまり、あの音は画像データを音波に変換したものなんです。 -->
<!-- 電話線って元々音声を送るための回線なので、データを一度「音」に変換しないといけない。 -->
<!-- これをやるのがモデムです。modulate（変調）と demodulate（復調）を合わせた略語ですね。 -->
<!-- そして、この変換のやり取りのルールを取り決めているのが「プロトコル」です。 -->

# あの音の正体 — **T.30 プロトコル**

- ITU-T が定めた FAX 通信の国際規格（初版 **1976年**、最終改訂 **2007年**）
- あの音はプロトコルに従った **機械同士の会話**

| フェーズ | 内容 |
|---------|------|
| **Phase A** | 端末確認（お互い FAX と認識） |
| **Phase B** | 能力交換・設定決定・回線テスト |
| **Phase C** | 画像データ転送 |
| **Phase D** | ページ終了・切断処理 |

<!-- あの音には、国際規格で定められたちゃんとした意味があります。 -->
<!-- ITU-T T.30 というプロトコルで、1976 年に初版が出て、最後の改訂は 2007 年です。 -->
<!-- FAX 通信は大きく 4 つのフェーズに分かれていて、それぞれで違う信号をやり取りしています。 -->
<!-- では 1 つずつ見ていきましょう。 -->

# Phase A — 「お互い FAX だよね？」

## CNG（Calling Tone） — 送信側が送る
- 周波数：**1100 Hz**、パターン：0.5秒ON → 3秒OFF の繰り返し
- 意味：**「私は FAX です！受信してください」**

## CED（Called Terminal Identification） — 受信側が応答
- 周波数：**2100 Hz**、パターン：**3秒間連続**
- 意味：**「こちらも FAX です！準備できてます」**
- 副作用：回線の **エコーキャンセラーを無効化** して通信を安定させる

<!-- まず Phase A、挨拶フェーズです。 -->
<!-- 送信側が 1100Hz の「ピッ、ピッ、ピッ」という断続音を鳴らします。これが CNG 信号。 -->
<!-- 「私は FAX ですよ、人間じゃないですよ」と自己紹介しているわけです。 -->
<!-- 受信側がそれを検知して 2100Hz の「ピー」という連続音を返します。これが CED 信号。 -->
<!-- 2100Hz はエコーキャンセラーを無効化する効果もあって、回線を安定させる役割もあるんです。 -->

# Phase B — 「何ができる？どれだけ速い？」

## DIS（Digital Identification Signal） — 受信側が送る
- **「自分はこれができます」** と能力を通知
- 対応解像度・用紙サイズ・最大通信速度・符号化方式など

## DCS（Digital Command Signal） — 送信側が返す
- DIS を受けて **「じゃあこの設定で送ります」** と確定
- 実際の通信速度・符号化方式・解像度を決定

> V.21 300bps の HDLC フレームでやり取りされる

<!-- 挨拶が済んだら、次は能力交換です。 -->
<!-- 受信側が「私は 14400bps で通信できます、A4 も B4 も受け取れます」という情報を送ります。これが DIS。 -->
<!-- 送信側がそれを受けて「じゃあ 9600bps で、MH 符号化で送るね」と決定するのが DCS。 -->
<!-- まるで「どんな言語で話す？」「英語にしよう」みたいな交渉ですね。 -->

# Phase B — 「ちゃんと届いてる？」

## TCF（Training Check Function） — 送信側
- **1.5秒間、0だけのデータ** を送信して回線品質を確認

## CFR / FTT — 受信側の返答
- **CFR**（Confirmation to Receive）：「OK！画像送ってください」
- **FTT**（Failure to Train）：「品質が悪い、速度を下げて」→ リトライ

## これが生み出すのが「ヒョロロロ」の音
- モデムがトーン周波数を変化させながら **最適速度を探る** 様子

<!-- ここが一番面白いところです。 -->
<!-- 能力交換で決めた速度で本当に通信できるか、テストするんですね。 -->
<!-- 送信側が 1.5 秒間ゼロデータを送ります。これが TCF。 -->
<!-- 受信側がきちんと受け取れたら CFR で「OK」、ダメだったら FTT で「速度下げて」と言います。 -->
<!-- このトレーニング信号こそが、あの「ヒョロロロ…」という独特な音の正体なんです。 -->

# Phase C/D — 「では送ります！以上！」

## Phase C — 画像転送
- トレーニング完了後、**実際の画像データを転送**
- MH/MR/MMR 符号化で圧縮（白が多いほど高圧縮）→「ジャー…」の音

## Phase D — 終了処理

| 信号 | 意味 |
|-----|-----|
| MPS | まだページが続きます |
| EOP | 最終ページ、終わります |
| MCF | 正常に受信しました |
| DCN | 切断します |

<!-- いよいよ画像本体を送るフェーズです。 -->
<!-- 白黒 2 値データを MH 符号化などで圧縮して送ります。白が多い文書ほど圧縮率が高くなります。 -->
<!-- 送り終わったら終了処理。複数ページあれば MPS で「次もあるよ」、 -->
<!-- 最後のページが終わったら EOP を送って、受信側が MCF で「受け取りました」、 -->
<!-- 最後に DCN で「切断します」と言って通話が終わります。 -->

# 全体の流れ

```
送信側                         受信側
  │─── CNG (1100Hz) ──────────→│  「FAX です！」
  │←── CED (2100Hz) ───────────│  「こちらも FAX！」
  │←── DIS ────────────────────│  「私の能力は…」
  │─── DCS ───────────────────→│  「この設定で！」
  │─── TCF (1.5秒テスト) ──────→│  「届いてる？」
  │←── CFR ────────────────────│  「OK！送って！」
  │─── 画像データ ─────────────→│  (ジャーーー)
  │─── EOP ───────────────────→│  「以上です」
  │←── MCF ────────────────────│  「受信完了！」
  │─── DCN ───────────────────→│  「切断します」
```

<!-- 「こんにちは」「こんにちは」「あなたの能力は？」「これです」 -->
<!-- 「じゃあこの速度で」「OK」「テスト」「受け取れた」「本番データ」「受け取った」「切断」 -->
<!-- 機械は毎回こういう丁寧なやり取りをしているわけです。 -->

# まとめ

- FAX は **1843年** 発明の超古参技術、今も現役
- あの音は **T.30 プロトコル** に従った「機械同士の会話」
- **CNG** → **CED** → **DIS/DCS** → **TCF/CFR** → **画像転送** → **DCN**
- 「ピー」「ヒョロロ」「ジャー」にはそれぞれ **意味がある**
- 電話回線でデータを送るための **精巧な仕組み**
