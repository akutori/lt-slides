# memo: オンプレ脳、クラウド脳

## 前提(想定時間・枚数・ツール・作成日)

- 想定時間: 10分(5分版は作っていない)
- 枚数: 10枚(タイトル1、見出し3、本文5、まとめ1)
- ツール: Marp(marp-cli 4.5.1)。図は Mermaid を事前レンダリングして画像化
- 作成日・出典の確認日: 2026-10-09
- 位置づけ: 意見のLT。「どちらが正しいか」ではなく「どこで切り替えるか」に着地させる
- 「脳」は発表者のラベル(題は発表者が考えたもの)。一般用語としては書いていない
- 軸は差し替え可能
  - 3つの比較軸(用意する / 壊れたとき / お金)は、過去のやりとりで提案された案であり、発表者が採用を決めたものではない
  - シードの案のうち「障害が起きたときに最初に疑う場所」は、裏が取れる一般論として「壊れたとき(壊れない設計と、壊れる前提の設計)」を本線にした。「最初に疑う場所」は差し込み欄(S6)に回した
  - 軸を替える場合に直す所: S3(「比べる軸」の行とセリフの末尾)、S4〜S6(「3つの違い」の見出し、表、セリフ)、S10(2項目目とセリフ)
- 発表者の経験として使った範囲(シードにあるものだけ)
  - 題名は発表者が考えた。オンプレ中心の人とクラウド中心の人で、考え方や意識が大きく違うという「若干の経験」から来ている
  - CTI/PBXなどオンプレ寄りの経験が長い。近年は、クラウド(GCP)と Terraform を使うプロジェクトにも関わった
  - 状態を持つサーバーを Stateful MIG + Autohealing に任せる設計を検討・評価した。検討であり、運用実績ではない
- スライド上の目印
  - 「(発表者の整理)」「(発表者の読み取り)」「(発表者の意見)」「(仮定)」は、出典のない発表者側の記述
  - 「2026年10月時点」は、変わりうる情報(S8、S9)
- セリフ量: 2310字(差し込み行を除く) / 2382字(差し込み行を含む)
  - 1分300字換算で約8分。差し込み2か所(各1分前後を想定)を足して10分に収まる見込み
  - 差し込みを入れなくても、事実の部分だけで話は通る
- S8 の図は縦長のため、`![h:380]` ではなく `![bg right:30% fit]` で右側に置いた(h:380 だと図中の文字が読めない)
- 匿名化: 顧客名・案件名・日付・個別の障害の詳細・具体的な数値は載せていない。電話番号・IP・認証情報も載せていない

## 質問されそうな点(3〜5個、答えと出典つき)

1. 「ペットと家畜」は、誰の言葉か
   - 答え: Randy Bias の2016年の記事によれば、Bill Baker の講演「Scaling SQL Server」で使われたたとえが起源。Baker 自身はクラウドの話をしていなかった。Randy Bias が2011〜2012年ごろにその講演を知り、クラウドの説明に使った。Baker の所属は記事に書かれていないので、言わない
   - 出典: https://cloudscaling.com/blog/cloud-computing/the-history-of-pets-vs-cattle/
2. Stateful MIG は、何を引き継ぐのか
   - 答え: インスタンス名、永続ディスク、IPアドレス、メタデータ。再起動・再作成・autohealing・更新を通して維持される。メモリ上の状態は、確認した説明に記載を見つけられなかった(発表者の読み取り。実機は未確認)
   - 出典: https://docs.cloud.google.com/compute/docs/instance-groups/stateful-migs / https://docs.cloud.google.com/compute/docs/instance-groups/preserved-state
3. 起動ディスクが壊れていたら、Autohealing で直らないのか
   - 答え: ステートフルなディスクが壊れていると、VM を作り直しても、そのディスクが再接続されるため、直らないことがある。公式は、ブートディスクなどを stateless に保ち、データは別のステートフルディスクに置くよう勧めている(2026年10月時点)
   - 出典: https://docs.cloud.google.com/compute/docs/instance-groups/preserved-state
4. プライベートクラウドは、敷地内に置くものではないのか
   - 答え: NIST SP 800-145 の定義では、「may exist on or off premises」、つまり敷地内にも敷地外にもありうる。発表者の「脳」は、置き場所の違いではなく、前提の違いという整理
   - 出典: https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-145.pdf
5. クラウドでも、固定費にしたり、敷地内に置いたりできるのか
   - 答え: Google Cloud には、利用量や支出を約束して割引を受ける確約利用割引(CUD)がある。敷地内やエッジに置く製品として Google Distributed Cloud がある。AWS にも Outposts がある(いずれも2026年10月時点)。割引率や条件は確認していないので、言わない
   - 出典: https://docs.cloud.google.com/docs/cuds / https://cloud.google.com/distributed-cloud / https://aws.amazon.com/outposts/
