# 構造化データとして扱う

<!-- ここから、コマンドの出力やファイルがデータとして扱える様子を、実行結果で見ます。 -->

---

<!-- header: 構造化データとして扱う -->
<!-- footer: https://www.nushell.sh/book/quick_tour.html<br>https://www.nushell.sh/book/types_of_data.html -->

```nu
ls | where type == file and size > 1kb | sort-by size
╭───┬───────────────┬──────┬─────────┬──────────────╮
│ # │     name      │ type │  size   │   modified   │
├───┼───────────────┼──────┼─────────┼──────────────┤
│ 0 │ notes.txt     │ file │  1.4 kB │ 2 months ago │
│ 1 │ README.md     │ file │  2.3 kB │ a day ago    │
│ 2 │ app.log       │ file │ 12.0 kB │ 2 days ago   │
│ 3 │ backup.tar.gz │ file │ 58.0 kB │ a month ago  │
╰───┴───────────────┴──────┴─────────┴──────────────╯

ls | describe
table<name: string, type: string, size: filesize, modified: datetime> (stream)
```

<!-- さて、まずはファイル一覧のコマンドです。 -->
<!-- 結果は、表になります。 -->
<!-- 列は、名前や種類、サイズなどです。 -->
<!-- 左端の数字は、行の番号です。 -->
<!-- なお、ディレクトリの中身は、デモ用のダミーです。 -->
<!-- で、この表を、続けて絞り込みます。 -->
<!-- そこで、パイプでつないで、前の結果を次に渡します。 -->
<!-- まず、ファイルだけに絞るのに、種類の列を使っています。 -->
<!-- そして、サイズが一定より大きいものだけを残します。 -->
<!-- サイズの比較には、大なり記号を使っています。 -->
<!-- 次に、サイズの列で並べ替えます。 -->
<!-- ここがポイントです。 -->
<!-- サイズの列は、専用の型になっています。 -->
<!-- つまり、単位まで含めて、大きさを比べられます。 -->
<!-- 文字順だと、大きさの順にならないことがあります。 -->
<!-- 同じ操作は、公式のクイックツアーにも載っています。 -->
<!-- 画面の下のコマンドで、列の型も確認できます。 -->

<!-- footer: https://www.nushell.sh/book/quick_tour.html<br>https://www.nushell.sh/book/operators.html -->

```nu
ps | where name =~ demo-job
╭───┬─────┬──────┬────────────┬──────────┬──────┬────────┬─────────╮
│ # │ pid │ ppid │    name    │  status  │ cpu  │  mem   │ virtual │
├───┼─────┼──────┼────────────┼──────────┼──────┼────────┼─────────┤
│ 0 │ 357 │  347 │ demo-job-a │ Sleeping │ 0.00 │ 1.6 MB │  2.7 MB │
│ 1 │ 358 │  347 │ demo-job-b │ Sleeping │ 0.00 │ 1.6 MB │  2.7 MB │
╰───┴─────┴──────┴────────────┴──────────┴──────┴────────┴─────────╯
```

- ps もプロセスの表を返し、ls と同じ where で絞り込める
- 列の名前(name、status、mem など)を指定して扱う
- 従来の ps は、先頭に ^ を付けて外部コマンドとして呼べる

<!-- さて、次はプロセスの一覧です。 -->
<!-- ここでも、結果は表になります。 -->
<!-- 実は、一覧も、1行が1つのプロセスです。 -->
<!-- 実行結果は、ダミーのプロセスを2つ起動して取りました。 -->
<!-- 眠るだけなので、状態は、どちらもスリープです。 -->
<!-- 名前で絞り込んでいるので、出るのはその2つだけです。 -->
<!-- 条件には、正規表現の一致を使っています。 -->
<!-- で、絞り込みの書き方は、さっきと同じです。 -->
<!-- ここも、ポイントです。 -->
<!-- つまり、コマンドが変わっても、操作は変わりません。 -->
<!-- 列の名前を指定して、条件を書きます。 -->
<!-- メモリの列は、サイズと同じ型です。 -->
<!-- この一覧は、組み込み、つまりシェルに入っているコマンドです。 -->
<!-- 従来のpsを使いたいときは、頭にキャレットを付けます。 -->
<!-- 従来のシェルでは、出力は文字列のかたまりです。 -->
<!-- 優劣ではなく、扱うデータの形が違います。 -->

# 向き不向き

<!-- さて、最後に向いている場面と注意点を、公式ドキュメントの記述から整理します。 -->

---

<!-- header: 向き不向き -->
<!-- footer: https://www.nushell.sh/<br>https://www.nushell.sh/book/thinking_in_nu.html<br>https://www.nushell.sh/book/default_shell.html<br>https://github.com/nushell/nushell<br>https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap01.html -->

- **向き**: JSON、YAML、SQLite、Excelなどを、そのまま扱う(公式サイトの記載)
- **向き**: 組み込みコマンドは、OSをまたいで使える(公式の説明)
- **注意**: POSIX準拠は意図されていない
- **注意**: bashの構文には、動かないものがある(例: `>` は比較演算子)
- **注意**: ログインシェルにすると、POSIX前提のプログラムで問題が生じうる
- **注意**: 設計は成熟の過程で変わりうる(現行は0.x系)

# まとめ

- コマンドの出力を、列や項目を持つデータとして扱える
- ls や ps の出力を、列名を指定して絞り込み・並べ替えできる
- JSON や CSV を、open で読み込み、get や to json で取り出し・変換できる
- bash や POSIX とは別の構文のため、書き方が通用しない場合がある
- 最新の安定版は 0.116.1(2026年10月時点)で、設計は今後変わりうる
